# AGENTS.md — AI Coding Agent Guidelines for Yorkshire

This document defines the architecture, conventions, workflows, and strict rules for AI coding agents working on the **Yorkshire** codebase.

---

## 1. Project Overview & Tech Stack

- **Module**: `github.com/MuhAndriansyah/yorkshire`
- **Language**: Go `1.27+`
- **HTTP Router**: `github.com/go-chi/chi/v5`
- **API Contract & Codegen**: OpenAPI 3.0.3 (`contract/`) + `@redocly/cli` (bundling/docs) + `oapi-codegen/v2` (`internal/api/api.gen.go`)
- **Database & SQL Codegen**: PostgreSQL 15 + `jackc/pgx/v5` (`pgxpool`) + `sqlc` (`internal/database/sqlc/`)
- **Migrations**: `pressly/goose/v3` (`migrations/`)
- **Cache**: Redis 7.4 (`redis/go-redis/v9`)
- **Authentication & Security**: RS256 JWT (`golang-jwt/jwt/v5`) + `bcrypt` (`golang.org/x/crypto/bcrypt`) + UUIDv7 (`google/uuid`)
- **Validation**: `go-playground/validator/v10`
- **Logging**: Structured JSON logging via standard `log/slog`

## 2. Directory Structure & Architecture

Yorkshire follows a **Contract-First, Layered Architecture**:

```text
.
├── cmd/server/main.go             # Application entrypoint, DI wiring, graceful shutdown
├── contract/                      # OpenAPI 3.0.3 multi-file specification (Source of Truth for HTTP API)
│   ├── openapi.yaml               # Root OpenAPI specification
│   ├── paths/                     # Per-endpoint path definitions
│   └── components/                # Reusable schemas, responses, parameters, securitySchemes
├── migrations/                    # Goose SQL migration files (Source of Truth for DB schema)
├── internal/
│   ├── api/api.gen.go             # GENERATED by oapi-codegen (DO NOT EDIT MANUALLY)
│   ├── database/
│   │   ├── postgres.go            # pgxpool initialization
│   │   ├── queries/               # Raw SQL queries for sqlc (Source of Truth for DB queries)
│   │   └── sqlc/                  # GENERATED by sqlc (DO NOT EDIT MANUALLY)
│   ├── server/router.go           # Chi router setup & global middleware mounting
│   ├── handler/                   # HTTP transport layer (implements api.ServerInterface via composition)
│   ├── service/                   # Business logic layer (domain-driven packages, e.g., service/auth)
│   ├── apperror/                  # Domain error types (AppError) & PostgreSQL error translation
│   ├── response/                  # Standardized JSON HTTP response writers & central error handler
│   ├── validator/                 # Request struct validation & user-friendly field error formatting
│   ├── jwt/                       # RS256 JWT token generation and verification
│   ├── security/                  # Password hashing (bcrypt)
│   ├── cache/                     # Redis cache wrapper (fail-open / graceful degradation)
│   ├── config/                    # Environment configuration loader (caarlos0/env + godotenv)
│   └── logging/                   # Multi-writer JSON slog setup
├── files/                         # RSA PEM key pair (private_key.pem, public_key.pem)
├── oapi-codegen.yaml              # oapi-codegen configuration
├── sqlc.yaml                      # sqlc configuration
└── makefile                       # Development & code generation commands
```

## 3. Golden Rules for Agents

### Rule 1: Never Edit Generated Files Manually
- **NEVER** modify `internal/api/api.gen.go` or any file inside `internal/database/sqlc/*.go`.
- To change API models/routes: edit files under `contract/` and run `make oapi-generate`.
- To change database models/queries: edit `migrations/*.sql` and `internal/database/queries/*.sql`, then run `make sqlc-generate`.

### Rule 2: Strict Layer Boundaries
1. **Handler Layer (`internal/handler/`)**:
   - Responsible ONLY for: decoding JSON (`decodeJSONBody`), validating request structs (`a.validate.Struct`), calling service methods with domain input types, and writing HTTP responses (`response.JSON`, `response.ErrorMsg`, `response.ValidationError`, `response.HandleError`).
   - Must **NEVER** import `internal/database/sqlc` or write SQL/DB logic.
   - Always include `return` immediately after calling `response.HandleError`, `response.ErrorMsg`, or `response.ValidationError`.
   - Use **Struct Embedding (Composition)** in `internal/handler/handler.go` (`type Handler struct { *AuthHandler ... }`) so `Handler` satisfies `api.ServerInterface`.

2. **Service Layer (`internal/service/<domain>/`)**:
   - Organize each domain into clear files:
     - `interfaces.go`: Service interface (`<Domain>Service`).
     - `service.go`: Struct definition and constructor (`New<Domain>`).
     - `types.go`: Domain input/output DTOs (`RegisterInput`, `AuthOutput`, etc.). Do not leak `api.*` or `db.*` types into public service signatures.
     - `mapper.go`: Functions converting `db.*` models to domain output structs.
     - `errors.go`: Domain-specific `apperror.TranslateOptions` and helper (`translate<Domain>PgError`).
     - `<domain>.go`: Core business logic implementation.
   - Must **NEVER** import `net/http` or `internal/api`.
   - Use **UUID v7** (`uuid.NewV7()`) when generating new primary keys in Go.

3. **Data Access Layer (`internal/database/`)**:
   - Depend on `db.Querier` interface in services for testability.
   - Translate raw `pgx` / `pgconn` errors at the service boundary using `apperror.TranslatePgError`.

## 4. Standard Patterns & Conventions

### Adding a New API Endpoint
1. **Define Contract**:
   - Add request/response schemas in `contract/components/schemas/`.
   - Add response definitions in `contract/components/responses/`.
   - Create path specification in `contract/paths/<resource>.yaml`.
   - Register path and components in `contract/openapi.yaml`.
   - Include `x-oapi-codegen-extra-tags: validate: "..."` on request schema properties for `go-playground/validator` rules.
2. **Generate API Code**:
   - Run `make oapi-generate` (bundles `contract/openapi.yaml` into `tmp/openapi.bundled.yaml` and generates `internal/api/api.gen.go`).
3. **Database Migration & Queries (if needed)**:
   - Create migration: `make migration <migration_name>`
   - Write SQL query in `internal/database/queries/<domain>.sql`.
   - Run `make sqlc-generate`.
4. **Implement Service**:
   - Add business logic in `internal/service/<domain>/`.
5. **Implement Handler**:
   - Implement the new method required by `api.ServerInterface` on the domain handler in `internal/handler/<domain>_handler.go`.
   - Embed the domain handler in `internal/handler/handler.go` if it is a new domain.
6. **Wire Dependencies**:
   - Wire any new service/handler dependencies in `cmd/server/main.go`.

### JSON Decoding & Validation
- Always use `decodeJSONBody(w, r, &req)` in handlers. It enforces a 1 MiB body limit (`http.MaxBytesReader`), rejects unknown fields (`DisallowUnknownFields`), and prevents trailing JSON tokens.
- Validate decoded structs with `a.validate.Struct(req)` and return HTTP `422 Unprocessable Entity` using `validator.FormatErrors(err)`.

### Error Handling
- Services return `*apperror.AppError` via constructors in `internal/apperror`:
  - `apperror.BadRequest(msg)` (400)
  - `apperror.ErrUnauthorized(msg)` (401)
  - `apperror.NotFound(msg)` (404)
  - `apperror.Conflict(msg)` (409)
  - `apperror.Internal(err, msg)` (500)
- Handlers pass service errors directly to `response.HandleError(w, a.logger, err)`.

### Response Format
All HTTP responses follow the standard envelope in `internal/response/response.go`:
- **Success**: `{"status": true, "data": ..., "meta": ...}`
- **Error**: `{"status": false, "message": "..."}`
- **Validation Error (422)**: `{"status": false, "message": "validation failed", "errors": {"field": "reason"}}`

## 5. Essential Commands

| Task | Command |
| :--- | :--- |
| Build & Verify Compilation | `go build ./...` |
| Run Server | `make run` |
| Bundle OpenAPI & Generate Go Server/Models | `make oapi-generate` |
| Build HTML API Documentation | `make oapi-docs` |
| Generate Type-Safe SQL Code | `make sqlc-generate` |
| Create New SQL Migration | `make migration <name>` |
| Run Database Migrations Up | `make goose-up` |
| Start Postgres & Redis Containers | `docker compose up -d` |

Always run `go build ./...` after making changes to verify type safety and interface compliance before completing a task.
